What Was Fixed and Why
Background: Two Move-In Systems
The repo has two separate move-in builder implementations. The old system lives in apps/ts-move-in-out-angular/ + libs/ts/movein/ngx/ and uses MoveinOutService. The new system (the one with bugs, introduced in commit f29e1217) lives in libs/ts/events/ngx/ and uses a generalized EventService framework that any event (move-in, Ring Day, etc.) can plug into via configuration objects.

Architecture of the New System
Each event is defined as an AggiemapCustomMapConfiguration with:

configuration — metadata (id, zoom, mapCenter, etc.)
sources — LayerSource[] defining the event's map layers (with native sub-properties that get passed to JSAPI)
options — the builder questions; each option has effects.layers with conversions mapping user selections to SQL definitionExpression strings
references — enum-like layer ID keys
EventService.drawEvent() runs on map init, applies each conversion to its target layer's source, then calls mapService.loadLayers().

The critical architectural detail: mapService.generateLayer() builds layer props as:


props = { ...source, ...source.native }
native always overrides root-level. This was the root cause of Bug 1.

Bug 1 — Residence Hall Not Highlighted
Root cause: move-in.definitions.ts defines the RESIDENCE_HALL layer with native.definitionExpression: '1=0' (a "show nothing initially" placeholder). drawEvent() was setting the user's hall expression at the root level of source (via (source as esri.FeatureLayer).definitionExpression = value). But since generateLayer spreads native last, native.definitionExpression: '1=0' always overrode it. The building was never shown.

Fix in event.service.ts: Changed all expression reads/writes to target source.native.definitionExpression. Added a setExpression() helper that writes to native when present. Treats '1=0' as empty (so it's replaced, not AND'd with the real expression — (1=0) AND (Bldg_Number IN ('0415')) would still show nothing).

Bug 2 — Map Not Zooming to Selected Hall
Root cause: The old MoveinOutService.drawResidence() had explicit logic to query the loaded hall layer's features and call mapService.zoomTo({ graphics, zoom: 18 }). The new EventService.drawEvent() never had this — it just loaded layers and left the map at initial zoom: 16.

Fix — three files:

special-event.interface.ts: Added focusLayerId?: string to EventConfiguration
move-in.definitions.ts: Set focusLayerId: MOVE_IN_LAYERS.RESIDENCE_HALL in MoveInConfiguration
event.service.ts: After await loadLayers(), added a 100ms timeout to query the focus layer's features with returnGeometry: true and zoom to them at zoom 18
The focusLayerId mechanism is generic — any future event can use it.
